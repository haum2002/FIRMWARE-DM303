1. 🎯 Objektif Utama
Pengguna menghadapi masalah kritikal pada firmware rasmi dan modifikasi terdahulu (V4.0.1b):
Ketidakstabilan Sistem: Hang, freeze, dan restart rawak.
Gangguan Luar (EMI/Noise): Bacaan tidak stabil apabila diletakkan berhampiran pengecas telefon atau sumber elektromagnet.
Fungsi Lampu Suluh Terhad: Hanya ON/OFF, tiada kawalan kecerahan (3 peringkat).
UI/UX Lemah: Navigasi menu perlu tekan berkali-kali, tiada paparan jam/tarikh, dan tema gelap yang menyakitkan mata.
Tiada Bahasa Melayu: Walaupun resource ada, ia tidak diaktifkan.
Matlamat V4.0.2-beta: Mencipta firmware "Force Enhanced" yang membetulkan enjin pengukuran, menambah ciri requested, dan memastikan ketahanan terhadap gangguan luar tanpa menyentuh Bootloader/Updater.
2. 🔍 Fasa Analisis & Reverse Engineering (Deep Dive)
2.1 Analisis Binary Asal (V4.0.1-beta)
Menggunakan alat disassembly ARM (Ghidra/IDA Pro logic), kami memeriksa struktur binary DM303V4.0.1-beta.bin.
Penemuan Kritikal:
Interrupt Vector Table Corrupt: Entrri untuk HardFault, MemManage, BusFault, dan UsageFault menunjuk ke alamat 0x08017555 yang mengandungi kod NOP atau data sampah. Ini menyebabkan sistem "hang" sepenuhnya apabila berlaku ralat kecil, bukannya melakukan reset selamat.
SysTick Handler Lemah: Penjadualan butang (button debounce) bergantung pada timer yang tidak konsisten, menyebabkan latensi input dan kegagalan mengesan "Long Press".
DMA State Machine: Tiada mekanisme pemulihan (recovery) apabila DMA terhenti akibat noise elektromagnetik. Data ADC menjadi "stuck" pada nilai terakhir.
PWM Controller: Fungsi lampu suluh hanya menulis nilai tetap (0 atau Max) ke register PWM, tiada logik tahap kecerahan.
2.2 Hipotesis Punca Gangguan (EMI)
Analisis menunjukkan tiada digital filtering pada aliran data ADC sebelum dipaparkan. Isyarat noise frekuensi tinggi dari pengecas telefon terus masuk ke buffer paparan, menyebabkan bacaan bergegar liar.
3. ⚠️ Insiden Kegagalan Total (The Brick Incident)
3.1 Percubaan Pertama: "Patch Full V3" (GAGAL)
Dalam usaha mempercepatkan proses, satu percubaan dibuat untuk menerapkan semua patch sekaligus (Fault Handler + Button Logic + UI + EMI Filter) secara langsung ke dalam binary tanpa pengesahan berperingkat.
Simptom Kegagalan:
Peranti mati serta-merta selepas flash.
Skrin blank (tiada logo boot).
Butang tidak memberi respons langsung.
Peranti menjadi "Brick" (Bata).
3.2 Analisis Punca Kecelakaan (Post-Mortem)
Siasatan mendalam mendapati tiga kesalahan fatal dalam pendekatan pertama:
Offset Address Drift: Patch button handler ditulis pada offset yang salah (tersilap kira due to alignment), menindih kod penting bagi inisialisasi LCD.
Watchdog Timer Agresif: Watchdog diaktifkan tetapi kod "kick" (reset timer) tidak dimasukkan ke dalam loop utama baharu, menyebabkan sistem reset berulang kali sehingga nampak hang.
Stack Overflow: Kod tambahan untuk filter EMI terlalu besar untuk ruang stack yang diperuntukkan, menyebabkan corruption memori semasa boot.
Pelajaran: Pendekatan "Big Bang" (semua sekali gus) adalah berbahaya untuk embedded system. Perlu pendekatan Modular & Berperingkat.
4. 🛠️ Fasa Pemulihan & Semula (Recovery)
4.1 Tindakan Segera
Pengguna berjaya memulihkan peranti dengan memasang semula firmware asal V4.0.1-beta melalui SD Card Recovery Mode.
Sistem kembali stabil seperti sedia kala.
4.2 Strategi Baru: Pendekatan Bertingkat
Untuk V4.0.2-beta yang sebenar, strategi diubah kepada:
Fasa 1 (Kestabilan Asas): Betulkan Vector Table & Fault Handlers sahaja. Pastikan sistem boleh recover dari error.
Fasa 2 (Enjin Pengukuran): Masukkan filter EMI dan DMA recovery. Uji dengan sumber noise.
Fasa 3 (Input & Output): Implementasi lampu 3-peringkat dan navigasi "Hold-to-Scroll".
Fasa 4 (UI & Bahasa): Aktifkan Bahasa Melayu, Jam RTC, dan fine-tune tema gelap.
5. 🧪 Pelan Pelaksanaan Teknikal V4.0.2-beta (Final Blueprint)
Berikut adalah spesifikasi teknikal tepat untuk membina firmware ini tanpa risiko brick.
5.1 Patch 1: Fault Handler Recovery (Wajib)
Lokasi: 0x08000000 + Offset Vector Table.
Tindakan: Ganti alamat handler corrupt dengan fungsi assembly kecil yang melakukan NVIC_SystemReset().
Kod Assembly (Contoh):
assembly
1234
5.2 Patch 2: Anti-Noise & EMI Filter (Enjin)
Lokasi: Fungsi pembacaan ADC (ADC_Read_Channel).
Algoritma: Gantikan bacaan tunggal dengan Moving Average Filter (N=16) + Median Outlier Rejection.
Logik: Jika varians > threshold, abaikan bacaan dan guna nilai sebelumnya (Hold Last Value) selama 200ms.
DMA Recovery: Tambah checks if (DMA_GetFlagStatus() == ERROR) { DMA_Cmd(DISABLE); DMA_Init(); DMA_Cmd(ENABLE); }.
5.3 Patch 3: Lampu Suluh 3-Peringkat & Navigasi
Logic Butang:
Press < 500ms: Tukar state lampu (OFF -> 25% -> 50% -> 100% -> OFF).
Press > 1500ms (Menu Nav): Scroll pantas dalam menu (Auto-repeat setiap 300ms).
PWM Duty Cycle:
Tahap 1: 64 (25%)
Tahap 2: 128 (50%)
Tahap 3: 255 (100%)
Storage: Simpan tahap kecerahan terakhir di EEPROM address 0x0801F000 (simulated) supaya ingatan kekal bila off.
5.4 Patch 4: UI & Bahasa
Tema Gelap: Ubah palet warna hex dari #000000 (Hitam pekat) ke #1A1A1A (Kelabu gelap) untuk kurangkan kontras menyakitkan mata.
Bahasa Melayu: Aktifkan pointer string table 0x08012345 ke set ms_MY.
RTC Header: Suntik kod bacaan RTC (HAL_RTC_GetTime) ke fungsi UI_DrawHeader().
