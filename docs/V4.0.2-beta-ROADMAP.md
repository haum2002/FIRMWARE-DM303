## 📋 Ringkasan Eksekutif

Dokumen ini mengemaskini pelan pembangunan firmware V4.0.2-beta berdasarkan pembelajaran daripada insiden "brick" dan audit keselamatan yang mendapati patch sebelumnya menindih kod executable.

### Prinsip Utama
1. **Keselamatan dahulu** - Hanya patch yang disahkan pada tahap byte boleh digunakan
2. **Pendekatan modular** - Satu ciri pada satu masa, diuji sebelum tambah yang berikutnya
3. **Verifikasi binary** - Setiap offset patch mesti disahkan dengan disassembly
4. **Rollback mudah** - Sentiasa ada laluan kembali ke firmware asal

## ⏸️ Fasa 3: INPUT & OUTPUT (PERLU VERIFIKASI HARDWARE)

### 3.1 Lampu Suluh 3-Peringkat 🔦

#### Analisis Hardware Diperlukan:
```
Kawasan kajian:
1. GPIO pin untuk backlight - dikenalpasti: GPIOD bit 0x08
2. Adakah PWM hardware available? - TIDAK DIKETAHUI
3. Timer assignment untuk PWM - PERLU DISASSEMBLY
```

#### Penemuan Audit Sebelumnya:
- Key code 0x1e memanggil function di 0x080185bc
- Function tersebut toggle state byte di 0x20000156
- Set/reset GPIOD bit 0x08
- **Ini adalah digital ON/OFF path, BUKAN PWM**

#### Pilihan Implementasi:
1. **Software PWM** - Insert routine baru, feed ke GPIO
   - Kelebihan: Tidak perlu hardware PWM
   - Kekurangan: CPU overhead, mungkin flicker

2. **Hardware PWM Hook** - Cari dan modify timer config
   - Kelebihan: Clean implementation
   - Kekurangan: Perlu reverse engineering mendalam

3. **Deferred** - Kekalkan ON/OFF untuk sekarang
   - **DISYORKAN** untuk V4.0.2-beta SAFE

### 3.2 Navigasi "Hold-to-Scroll"

#### Patch Yang Dirancang:
```
Offset 0x08B20: Extend button debounce (10→30 ticks) ✅ SUDAH DIAPPLY
Offset 0x08C45: Long-press detection ❌ GAGAL - overwrite executable
```

#### Tindakan Diperlukan:
1. Disassemble button handler routine
2. Cari location untuk long-press timeout logic
3. Verify tidak overwrite instruction penting

## ⏸️ Fasa 4: UI & BAHASA (PERLU LOKASI TEPAT)

### 4.1 Bahasa Melayu 🇲🇾

#### Status Semasa:
- ✅ TEXT_MS.DAT sudah tersedia dalam `/system`
- ❌ Lokasi language table TIDAK DIKETAHUI

#### Audit Sebelumnya:
```
Offset 0x05210: Didakwa "activate Bahasa Melayu"
MASALAH: Overwrites executable code:
  87 21 40 F2 3F 13 00 22 ...
  Ini adalah instruction ARM Thumb, BUKAN data table!
```

#### Tindakan Diperlukan:
1. **Search untuk language pointer table**
   - Cari pattern: pointer ke string "ENGLISH", "BAHASA", dll
   - Biasanya struktur array of pointers

2. **Verify TEXT_MS.DAT format**
   - Bandingkan dengan TEXT_EN.DAT
   - Pastikan offset dan saiz sama

3. **Patch language selector menu**
   - Cari menu rendering function
   - Add "Bahasa Melayu" sebagai pilihan

### 4.2 RTC Clock Display 🕐

#### Keperluan:
- Bacaan dari HAL_RTC_GetTime()
- Render ke header UI
- Format: HH:MM:SS DD/MM/YYYY

#### Analisis Diperlukan:
1. Adakah RTC hardware initialized dalam firmware asal?
2. Cari panggilan RTC functions (jika ada)
3. Identify header rendering function
4. Inject RTC read + display code

#### Risiko:
- Jika RTC hardware tidak ada/tak berfungsi → crash
- Perlu fallback ke software timer jika RTC fail

### 4.3 Battery Percentage 🔋

#### Status:
- ADC monitoring untuk battery voltage mungkin sudah ada
- Perlu cari location untuk enable percentage calculation

#### Tindakan:
1. Search ADC channel untuk battery voltage
2. Cari formula conversion voltage → percentage
3. Inject render call ke UI status bar

### 4.4 Dark Theme Fine-tuning 🎨

#### Masalah Audit Sebelumnya:
```
Offset 0x0E100-0x0E130: Didakwa color palette
MASALAH: Overwrites decimal/string rendering code!
```

#### Pendekatan Betul:
1. **Cari actual color palette table**
   - Search untuk nilai RGB berulang (contoh: 00 00 00 untuk hitam)
   - Biasanya dalam data section, bukan code section

2. **Verify dengan pattern matching**
   - Color tables biasanya contiguous blocks
   - Nilai dalam range 0x00-0xFF untuk R,G,B

3. **Alternative**: Skip untuk V4.0.2-beta
   - Dark theme sudah ada dalam V4.0.1b
   - Fine-tuning boleh dibuat kemudian

## 🛡️ PROTOKOL KESELAMATAN PATCH

### Checklist Pra-Patch:
- [ ] Binary analysis disahkan dengan Ghidra/IDA atau tool serupa
- [ ] Offset patch verified dengan multiple methods:
  - Pattern matching (before bytes)
  - Context analysis (sebelum & selepas)
  - Instruction decoding (jika code region)
- [ ] Guard condition: Skip patch jika before bytes tidak match
- [ ] Backup firmware asal disimpan

### Checklist Pasca-Patch:
- [ ] SHA-256 checksum dijana
- [ ] Perbezaan byte didokumentasikan
- [ ] Report dijana dengan semua perubahan
- [ ] System files disalin lengkap

### Testing Checklist:
- [ ] Device boot normally
- [ ] Semua button berfungsi
- [ ] Display normal (no artifacts)
- [ ] Measurement stabil
- [ ] Update function masih berfungsi
- [ ] No hang/freeze dalam 30 minit operasi

## 📝 PENUTUP

Pembangunan firmware V4.0.2-beta kini mengikuti pendekatan **keselamatan-first**. Daripada tergesa-gesa menambah semua ciri sekaligus, kita fokus pada:

1. **Stability** - Pastikan device tidak hang/crash
2. **Verifiability** - Setiap patch boleh diaudit pada byte level
3. **Recoverability** - Mudah rollback jika ada masalah

Firmware V4.0.2-beta SAFE adalah asas yang kukuh untuk pembangunan seterusnya. Features tambahan akan ditambah secara berperingkat setelah melalui proses verifikasi yang ketat.
